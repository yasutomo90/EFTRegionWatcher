# EFTRegionWatcher

Escape from Tarkov のログに記録された接続先 IP を読み取り、推定地域を表示する Windows 11 x64 用の非公式ツールです。
480 × 592 の Win32 ウィンドウと通知領域（システムトレイ）で動作します。

データ源はログファイルだけです。
ゲームメモリの読み取り、DLL 注入、フック、パケットキャプチャ、ゲーム操作の自動化はいずれも行いません。
日本語フォント（Noto Sans JP）を実行ファイルに同梱するため、フォントの追加インストールも不要です。

最新版は [Releases](https://github.com/yasutomo90/EFTRegionWatcher/releases) から入手できます。
公開先は [github.com/yasutomo90/EFTRegionWatcher](https://github.com/yasutomo90/EFTRegionWatcher) です。

## 起動と初期設定

ローカルで作成した配布物は `target/dist/EFTRegionWatcher.exe` です。
公開後は GitHub の Releases から `EFTRegionWatcher.exe` をダウンロードし、書き込み可能なフォルダに保存してダブルクリックします。
初回はメイン実行ファイルだけで起動できます。
更新用の `EFTRegionWatcher.Updater.exe` は、更新のときにアプリが取得します。
ZIP には両方の実行ファイルと説明書を同梱しますが、通常の更新で ZIP を手動展開する必要はありません。

1. アプリを起動します。管理者として実行する必要はありません。
2. ログフォルダを、レジストリのアンインストール情報と既定のインストール先から探します。見つからない場合は「設定」で EFT の `Logs` フォルダを選びます。
3. EFT で接続ログが書かれると、IP と推定地域を表示します。過去の接続は「接続ログ」タブに並びます。
4. 初期設定では、ウィンドウを閉じるとアプリが終了します。設定でトレイに残すこともできます。
5. 終了するときは、画面右下の「終了」か、トレイアイコンの右クリックメニューの「終了」を選びます。

## 画面の構成

ウィンドウ上部にタブが 2 つあります。

| タブ | 内容 |
|---|---|
| 現在の接続 | 接続状態、推定地域、接続先 IP、検出時刻 |
| 接続ログ | 過去の接続履歴。1 ページ 5 件、マウスホイールで 1 ページずつ送ります |

履歴はメモリ上に最大 200 件だけ保持します。ファイルには書き出しません。

右上の「設定」ボタンで設定画面に切り替わります。設定画面で操作できる項目は次のとおりです。

| 項目 | 初期値 | 説明 |
|---|---|---|
| ログフォルダ | 自動検出 | 「変更」から EFT の `Logs` フォルダを選び直します |
| ダークモード | オン | ダーク配色とライト配色を切り替えます |
| 閉じてもトレイに残す | オフ | オフのときは × と Alt+F4 でアプリが終了します |
| 接続通知 | オフ | 新しい接続先を検出したときにトレイ通知を出します |
| 自動更新チェック | オン | 起動時に更新を確認します |

設定画面では、「更新を確認」で手動確認、右下の「終了」でアプリの終了ができます。
キーボードからは、Esc で設定画面を閉じ、Enter でフォーカス中のボタンを実行します。

トレイアイコンを左クリック（またはダブルクリック）するとウィンドウが再表示されます。
右クリックメニューからは「開く」「現在のサーバー」「IP をコピー」「更新を確認」「設定」「終了」を選べます。
コピーする IP にポートは含みません。

## 表示の読み方

「現在の接続」タブの表示は次のようになります。

```text
[ 現在の接続 ]  [ 接続ログ ]

● 接続を検出          ログから接続先を確認

  推定地域
  Japan / Tokyo

  ───────────────────────────
  SERVER   203.0.113.10
  検出  2026/09/10 12:42:18
```

推定地域は「国 / 地域 / 都市」の形式です。行数に応じて文字サイズと行間を変え、都市名まで揃った 3 行の場合でもカード内に収まります。

「接続を検出」は、ログへの追記を検出した状態を示します。
本アプリが読むのはログの追記だけであり、切断はログから判別できません。
そのため接続が続いていることを保証する表示ではなく、追記の検出から 5 分が過ぎると「待機中／最後に検出したサーバー」に切り替わります。

地域は IP から推定したものです。
EFT が公表しているサーバー名ではなく、データセンターの実際の設置場所とも一致しないことがあります。

起動時に見つかった過去ログは、最初から最後の記録として扱います。
過去ログの「最終記録」時刻は、接続時刻ではなくファイルの更新時刻です。
古い形式ではポートが記録されていないため、その場合は「ポート不明」と表示します。

## 更新のしくみ

公開リリース版は、前回の確認から 24 時間以上が経っている場合に、起動時の更新チェックを行います。
確認間隔は 1〜168 時間の範囲で `config.toml` から変えられます。
トレイまたは設定画面の「更新を確認」からは、間隔によらず手動で確認できます。
ローカルビルドは公開先が未設定なので、自動では更新先へ通信しません。

更新が見つかったときの選択肢は 3 つです。

- 「更新する」：新しい実行ファイルをダウンロードし、検証してから置き換えます。
- 「あとで」：現在のバージョンを使い続けます。
- 「このバージョンをスキップ」：そのバージョンを再通知しません。次の新しいバージョンは対象になります。

EFT の起動中に更新すると実行ファイルの置き換えに失敗するため、「EFT 終了後に更新」を初期選択にします。
「今すぐ更新」と「キャンセル」も選べます。
EFT を終了させる操作は行いません。
終了を待っているあいだも、ログ監視と地域検索は動き続けます。
待機中に本アプリを終了すると、待機をキャンセルします。

ダウンロードしたファイルは、配布元 URL の確認、`SHA256SUMS.txt` との照合、PE ヘッダーの確認をすべて通過した場合だけ適用します。
どれかに失敗した場合、現在の実行ファイルは置き換えません。
置き換えや新バージョンの起動に失敗した場合は、バックアップ（`.previous`）から復元します。
SHA-256 は配布ファイルの整合性の確認であり、発行者を独立に証明する署名ではありません。
信頼の起点は、公開リポジトリと HTTPS です。

## 保存情報と通信

保存先は `%LOCALAPPDATA%\EFTRegionWatcher\` です。

| ファイル | 内容 |
|---|---|
| `config.toml` | ログフォルダ、表示テーマ、通知設定、更新設定 |
| `geo_cache.json` | IP と推定地域。通常 30 日間、最大 256 件 |
| `logs/app.log` | 小さな診断ログ。約 256 KiB で一世代（`app.old.log`）ローテーション |
| `updates/` | 承認した更新の作業用ファイル。7 日以上経過したものは起動時に削除 |

キャッシュにない公開 IP は、[ipwho.is](https://ipwhois.io/documentation) に HTTPS で送信します。
サービス側に伝わるのは、検索対象の IP と通常の HTTPS 接続情報です。
検索に失敗したときは IP を表示したまま、同じ IP への再試行を 10 分間抑制します。
プライベート IP と文書用 IP は外部へ送りません。

更新の確認とダウンロードには GitHub を使います。
EFT のログ全文、ゲームアカウント情報、解析情報をアップロードする機能はありません。
テレメトリー、広告、クラッシュの自動送信も実装していません。

## うまく動かないとき

| 症状 | 対処 |
|---|---|
| ログフォルダが見つからない | 「設定」から EFT のインストール先にある `Logs` を選択します。探索は選んだフォルダ以下に限られ、ディスク全体は検索しません。 |
| IP が表示されない | 対象ログに対応形式の接続記録があるか確認します。EFT のログ形式が変わった場合はパーサーの更新が必要です。 |
| ログフォルダを移動した | 「設定」で選び直します。 |
| 地域が取得できない | ネットワークと GeoIP サービスの状態を確認します。IP の検出は続きます。 |
| 更新できない | 保存先が書き込み可能か確認します。旧版はそのまま使い続けられます。 |
| 復元に失敗したと表示される | アプリを終了し、実行ファイルの隣にある `.previous` を保存してください。診断ログと合わせて開発者に連絡してください。 |
| セキュリティ製品で警告される | 配布元とハッシュを確認してください。現在はコード署名していません。セキュリティ機能を無効にする対処は勧めません。 |

停止はトレイの「終了」から行ってください。
終了時に通信が処理中の場合、タイムアウトまで少し待つことがあります。

## アンインストール

トレイの「終了」で停止し、保存した実行ファイルを削除します。
設定とキャッシュも消す場合は `%LOCALAPPDATA%\EFTRegionWatcher\` を削除します。
サービスやドライバーはインストールしないため、ほかに残るものはありません。

## ビルドと開発

ビルドには Rust stable（edition 2024）と Visual Studio Build Tools の C++ ビルド環境が必要です。
利用者の側に Rust や Visual Studio を用意してもらう必要はありません。

```powershell
cargo fmt --check
cargo clippy --locked --all-targets -- -D warnings
./scripts/test.ps1
cargo build --locked --release
./scripts/package.ps1
```

テストは、成功時に「異常なし」だけを表示し、失敗時は該当コマンドと出力内容を表示して終了コード 1 を返します。
実通信を伴うテストは通常の実行ではスキップし、`./scripts/test.ps1 -IncludeNetwork` を付けたときだけ実行します。
スクリプトの実行には PowerShell 7 が必要です。

補助スクリプトは 3 つあります。

| スクリプト | 用途 |
|---|---|
| `scripts/test.ps1` | 静かなテスト実行（`-IncludeNetwork` で実通信テストも実行） |
| `scripts/package.ps1` | `target/dist/` に実行ファイル・説明書・`SHA256SUMS.txt`・ZIP を生成 |
| `scripts/profile.ps1` | 空のログフォルダで一定時間動かし、待機時のメモリと CPU を記録 |

アイコンを差し替えるときは、`assets/icon.ico` を置き換えます。
ウィンドウ、トレイ、画面左上のマークはいずれも同じアイコンリソース（resource 1）を参照するので、再ビルドすれば 3 か所とも同時に切り替わります。

`cargo test` は、UI の描画結果を `target/ui-previews/` に PNG として書き出します（ダーク／ライト、各タブ、設定画面、200% 拡大）。
レイアウトを変えたときは、この PNG で目視確認できます。

対象は Windows x64 MSVC で、CRT は静的リンクします。
Cargo の実行ファイル名の制約により、ビルド直後の更新用バイナリ名は `EFTRegionWatcherUpdater.exe` です。
パッケージ作成時に `EFTRegionWatcher.Updater.exe` へ変更します。

### ソースの構成

| パス | 役割 |
|---|---|
| `src/eft/finder.rs` | ログフォルダの自動検出（レジストリ、既定のインストール先） |
| `src/eft/watcher.rs` | ログの監視と追記読み取り |
| `src/eft/parser.rs` | 接続行の解析 |
| `src/geo.rs` | 地域検索とキャッシュ |
| `src/net.rs` | WinHTTP による HTTPS 取得 |
| `src/update.rs` | 更新の確認、検証、適用 |
| `src/config.rs` | 設定の読み書きと診断ログ |
| `src/ui.rs` | ウィンドウ、トレイ、状態遷移 |
| `src/ui/style.rs` | 描画とレイアウト |

ログの監視には `notify` を使い、その Windows バックエンドは [ReadDirectoryChangesW](https://learn.microsoft.com/ja-jp/windows/win32/api/winbase/nf-winbase-readdirectorychangesw) を呼びます。
監視中は通知をブロック待機し、通知を受けたら追記部分だけを読みます。
ファイルが切り詰められた場合と置き換えられた場合は、読み取り位置をリセットします。
一時的な読み取り失敗に限り、500 ms 間隔で最大 4 回まで試行します。
起動直後の読み取りは各ログの末尾 64 KiB までとし、フォルダの探索は深さ 3、最大 1,024 ログファイル（走査ディレクトリ 2,048）で打ち切ります。

解析できるのは次の 2 形式です。

```text
Connect (address: 79.127.145.28:17007)
RaidMode: Online, Ip: 79.127.145.28
```

### 公開とリリース

Cargo のバージョンと同じ安定版タグ（例 `v0.1.0`）を push すると、release workflow が動きます。
workflow はリポジトリ名を `EFT_RELEASE_REPOSITORY` として埋め込んでビルドし、テストの成功後に GitHub Release を作成します。
CI が公開するのは、`EFTRegionWatcher.exe`、`EFTRegionWatcher.Updater.exe`、`SHA256SUMS.txt`、ZIP とそのハッシュです。
更新先が埋め込まれるのはこの経路でビルドしたものだけなので、手元でビルドした実行ファイルは自動更新を行いません。

### バージョン付けの規則

バージョンは [セマンティック バージョニング](https://semver.org/lang/ja/) に従い、`MAJOR.MINOR.PATCH` の 3 つの数字だけで表します。

| 上げる桁 | 上げる場面 |
|---|---|
| MAJOR | 設定ファイルの互換性が切れる、更新経路そのものが変わるなど、旧版からそのまま移行できない変更 |
| MINOR | 機能の追加、対応ログ形式の追加、画面の変更 |
| PATCH | 不具合の修正、文言と表示の調整、依存の更新 |

タグは、`Cargo.toml` の `version` に `v` を付けた形にします。
release workflow はタグ名と `Cargo.toml` のバージョンが一致することを確かめ、食い違っていればビルドの前に失敗します。
したがって、バージョンを上げるコミットとタグは必ず同じコミットを指します。

更新の通知には、次の条件をすべて満たす Release だけを使います。

- draft でも prerelease でもない
- タグに `-rc.1` のようなプレリリース識別子が付いていない
- 現在のバージョンより大きい
- 利用者が「このバージョンをスキップ」を選んだバージョンと一致しない

release workflow のバージョン検証は `MAJOR.MINOR.PATCH` の形しか受け付けないため、プレリリース版を Release として公開する手段は用意していません。
公開前の動作確認には、`build.yml` が push ごとに作る成果物（Actions の artifact）を使います。
